`11-shared-ui-i18n.md`. The JSON rows use this fixed column order:

`id | severity | disposition | delivery | owner | batch | locations | tests | rationale | duplicateOf`

Only `confirmed | duplicate | expected | accepted-risk` and
`planned | fixed | not-applicable` are valid. Owners are deliberately unique so every finding
has one accountable delivery slot. Duplicate rows resolve to one primary finding.

## Delivery Policy

Batches are delivered in order from P0 through P5. A confirmed row moves from `planned` to
`fixed` only with its implementation and named verification in the same batch. Expected and
accepted-risk rows are not code backlogs. Account hard erasure, step-up authentication, session
versioning, and changes to `db:push` or `db:drop` remain outside the approved scope.
